# كلاي | اللعب مع بعض

نموذج أولي لمنصة ألعاب جماعية عبر الويب: شاشة مضيف تنشئ غرفة، وأجهزة الهاتف تنضم عبر QR وتعمل كوحدات تحكم مستقلة.

## التشغيل

```bash
npm install
npm start
```

افتح `http://localhost:3000/host.html` على جهاز المضيف. يعمل الخادم على الشبكة المحلية دون إنترنت، ويظهر رابط الانضمام ورمز QR عنوان الشبكة تلقائياً. يجب أن تكون أجهزة التحكم على شبكة Wi-Fi نفسها، مع السماح بالاتصالات إلى المنفذ `3000` في جدار الحماية.

### التشغيل على Android

المشروع خادم Node.js وليس تطبيق APK. ثبّت Termux من F-Droid، ثم ثبّت Node.js ونسخة المشروع مرة واحدة مع اتصال الإنترنت:

```bash
pkg update
pkg install nodejs-lts git
git clone https://github.com/ah11026/klai.git
cd klai
npm install
npm start
```

افتح `http://127.0.0.1:3000/host.html` في متصفح الهاتف ليعمل عامل الخدمة على أصل آمن محلياً. اترك Termux يعمل في الواجهة الأمامية أثناء اللعب؛ يمكن استخدام `termux-wake-lock` لمنع إيقافه أثناء اللعب. امسح QR بأجهزة اللاعبين على الشبكة نفسها. لا تفعّل تحويل المنفذ إلى الإنترنت، لأن رفع الألعاب متاح بلا مفتاح إدارة.

### المكتبة والتشغيل دون إنترنت

تُحفظ الألعاب في `data/games` بجانب المشروع، وفهرسها في `data/games/catalog.json`. يمكن تغيير المجلد عبر `GAME_LIBRARY_DIR`. لا يوجد حد برمجي لعدد الألعاب أو لحجم اللعبة؛ الحد الفعلي هو المساحة الحرة على الجهاز. الملفات تُرفع على دفعات لتجنب وضع اللعبة كاملة في الذاكرة. احتفظ بنسخة احتياطية من مجلد `data/games`.

الألعاب التي كانت مرتبطة بمكتبة GitHub القديمة لا تنتقل تلقائياً؛ ارفع ملفاتها إلى الخادم المحلي من جديد. ملفات تلك الألعاب غير مضمنة في نسخة المشروع.

للاستخدام دون إنترنت، افتح التطبيق وحمّل كل لعبة وأصل محاكي تحتاجه مرة واحدة أثناء توفر الإنترنت؛ يخزّن المتصفح ملفات الواجهة والمحاكي والألعاب التي فُتحت في Cache API، ثم يستخدم النسخة المحلية عند انقطاع الإنترنت. مساحة هذا الكاش تخضع لحدود المتصفح وقد يمسحها النظام؛ الملفات الأصلية تبقى في مجلد بيانات الخادم. بعد تثبيت التبعيات وتهيئة الكاش لا يحتاج اللعب على الشبكة المحلية إلى اتصال إنترنت.

التأكد من حقك في استخدام ملفات الألعاب مسؤوليتك؛ حقول الترخيص تبقى لتوثيق مصدر الملف.

يمكن تشغيل الاختبارات باستخدام `npm test`.

### المحاكيات

تُشغّل صفحة `emulator.html` الألعاب عبر EmulatorJS باستخدام النوى: `fceumm` (NES)، `snes9x` (SNES)، `mupen64plus_next` (N64)، `pcsx_rearmed` (PS1)، و`melonds` (Nintendo DS). يمر تحميل ملفات EmulatorJS عبر الخادم المحلي ليتمكن المتصفح من تخزينها للاستخدام دون إنترنت. قد تحتاج بعض ألعاب PS1 إلى BIOS. PS2 غير مدعوم. تُرسل مدخلات كل هاتف إلى منفذ اللاعب المطابق؛ دعم اللعب الجماعي يعتمد على اللعبة والنواة.

## ما يشمله النموذج

- إنشاء غرفة برمز من ستة أرقام ورمز QR.
- انضمام حتى أربعة لاعبين، مع إعادة استخدام المقاعد الشاغرة.
- إرسال ضغطات الأزرار وإفلاتها إلى المضيف عبر Socket.IO، وتحرير الأزرار عند انقطاع اللاعب، وإعادة انضمام الهاتف بعد عودة الشبكة.
- التحقق من رسائل الإدخال وتحديد معدلها، وحماية طلب QR برمز سري خاص بالمضيف.
- بث الأحداث إلى طبقة المحاكي عبر حدث المتصفح `remote-game-input`.

## حدود التكامل

تعمل الأنظمة NES وSNES وN64 وPS1 وNDS عبر EmulatorJS عند فتح اللعبة من المكتبة. لا يشمل المشروع ملفات ألعاب. توفر وحدة الهاتف D-pad أو عصاً تناظرية يسارية، وأزرار الوجه والكتف، وتُرسل المدخلات مباشرة إلى مقعد اللاعب المطابق (حتى أربعة). العصا اليمنى غير موجودة في واجهة الهاتف حالياً، كما يعتمد اللعب الجماعي الفعلي على دعم اللعبة والنواة. PS2 غير مدعوم.

الغرف تُدار داخل عملية خادم واحدة. لا تعرض خادم المكتبة للإنترنت العام؛ ارفع الألعاب فقط على شبكة موثوقة.
